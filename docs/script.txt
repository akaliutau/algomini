ALGOMINI — THREE-MINUTE DEMO

Read the SAY paragraphs only. SCREEN, CAPTION and COMMANDS are production cues.
The narration is 335 words. Speak conversationally, around 135 words per minute;
that leaves about 31 seconds for the terminal and page changes. The seven scenes
total exactly 3:00.

00:00–00:22 | The problem

SCREEN: README hero and tagline; then the issue template link.

SAY:
Moving data costs time and bandwidth, especially on constrained links like
satellite internet. Compression can save storage and reduce the bytes we send.
We built Algomini to automate the search for compressors tailored to your
data, turning a research problem into software you can install.

00:22–00:48 | Two fields in GitHub

SCREEN: Briefly show the two books inside books2.zip. Open the issue form, with
plugin name text-v2 and the archive URL already filled in. Point to both fields.

SAY:
Let's pick two text files and put them in a ZIP. Ideally, they're different
samples of the same kind of data. With two files, the larger is for development;
the other is reserved for the final check. In GitHub, I enter a plugin name and
paste the archive link. That's the request.

00:48–01:18 | The research loop

SCREEN: Cut to completed issue #6 and its Actions run. Show the research step,
the generated Rust candidate, and briefly the .agents/skills directory.
CAPTION: Completed run #6 • Cloud waiting time omitted
CAPTION: Research: first 2 MiB of development data • Qualification: complete files

SAY:
Submitting kicks off the pipeline. Let's look at a completed run. Behind the
scenes, the lab probes the data and retrieves relevant skills. Meta's Muse Spark
writes Rust candidates and refines them using measured feedback. We compile and
test its proposals, with spending and execution limits. The final file stays
outside that coding loop.

01:18–01:46 | Show the evidence

SCREEN: Issue #6 result table. Highlight Final: 644,368 bytes versus xz's
764,445 bytes, saving 15.71%, Exact: yes. Briefly open Candidate trials and
highlight the Muse-generated candidate and the winning reviewed seed.
CAPTION: Recorded book sample • Complete archive bytes • Decoder size separate

SAY:
Let's see what happened. On this recorded book sample, the archive is fifteen
point seven percent smaller than xz, the strongest baseline we tested. Every
byte must be reconstructed, and models and framing count toward size. Muse
generated a candidate, but a reviewed codec won this run. We ship the measured
winner, and the report shows that decision.

01:46–02:05 | From research to a release

SCREEN: Merged PR #7, its report and source link; then Algomini v0.3.1 on the
Releases page. Show the Cargo installation command from the issue.

SAY:
Everything stays in GitHub: the request, experiments, results, and review.
That's where our development already happens. A passing result opens a pull
request; after human review and merge, the release workflow publishes an
installable Rust client.

02:05–02:40 | Use the actual compressor

SCREEN: Terminal, with the release already installed. Run the commands below.
Pause on the compressed byte count and the final "Exact match" message.
CAPTION: Dumas book sample • text-v2 • Installed from Algomini v0.3.1

SAY:
Now let's use it. Cargo installs the reviewed release. I select the plugin by
name and compress the book. Then I decompress it and compare it with the
original. Exact match. The compressor runs offline, with no model calls or
Python. The research produces software you can actually install and use.

COMMANDS:
algomini --version
algomini compress --plugin text-v2 sample.bin book.alc
algomini decompress book.alc restored.bin
cmp sample.bin restored.bin && echo "Exact match"

02:40–03:00 | Why it can improve

SCREEN: .agents/skills and the memory index, then return to the README hero.
Hold the closing tagline and repository URL until 03:00.

SAY:
We built the research lab, GitHub automation and Rust delivery during this
hackathon. Skills and development results stay reusable, so later experiments
can build on earlier evidence. Algomini: give your data its own compressor,
and make every byte count.
